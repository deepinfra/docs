[opencode](https://opencode.ai) is an open-source coding agent for the terminal, desktop and IDEs. DeepInfra is one of its built-in providers, so the only setup is an API key.

## Connect

1. Create an API key at [deepinfra.com/dash/api_keys](https://deepinfra.com/dash/api_keys).
2. In opencode, run `/connect`, pick **Deep Infra**, and paste the key.
3. Run `/models` and pick a model from the Deep Infra section.

Model ids have the form `deepinfra/<model>`, so the same model is `deepinfra/deepseek-ai/DeepSeek-V4.1-Flash-1017` on the command line and in config. Instead of `/connect`, you can also export `DEEPINFRA_API_KEY` before launching opencode, which is what scripts and sandboxes do.

To make a DeepInfra model the default, set it in `opencode.json`:

```json opencode.json
{
  "$schema": "https://opencode.ai/config.json",
  "model": "deepinfra/deepseek-ai/DeepSeek-V4.1-Flash-1017"
}
```

## Recommended models

| Model | Context | Good for |
|---|---|---|
| `deepseek-ai/DeepSeek-V4.1-Flash-1017` | 1M | Daily driver and by far the most-used DeepInfra model in opencode. Strong agentic coding at a low price, with the cheapest cache reads of the set. |
| `zai-org/GLM-5.3-Flash` | 1M | Budget option in a different model family. |
| `zai-org/GLM-5.3` | 1M | A second opinion when a task matters. |
| `moonshotai/Kimi-K3` | 1M | The hardest long-horizon tasks. The priciest and slowest of the set. |

See each model's page on [deepinfra.com/models](https://deepinfra.com/models) for current per-token pricing.

## Reasoning effort

opencode shows a model's reasoning levels as variants: pick one in `/models`, or pass `--variant <level>` to `opencode` or `opencode run`. The variant is sent to DeepInfra as `reasoning_effort`. The levels on offer per model (for example `none`, `low`, `high` and `max` on DeepSeek V4.1 Flash) come from [models.dev](https://models.dev), the catalog opencode reads.

## Prompt caching

Nothing to configure. opencode sends a per-session cache key with every request, so the repeated prefix of an agent session is billed at the model's cached-input rate. opencode shows the cached share as cache reads in its usage view.

## Models missing from the picker

opencode's model list comes from [models.dev](https://models.dev), which syncs prices and context sizes from DeepInfra's public catalog hourly but only lists a model once it has an entry for it. Any DeepInfra model you don't see in `/models` can be added in `opencode.json`:

```json opencode.json
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "deepinfra": {
      "models": {
        "nvidia/NVIDIA-Nemotron-3.5-Lightning": {
          "name": "Nemotron 3.5 Lightning",
          "limit": { "context": 262144, "output": 32768 },
          "cost": { "input": 0.06, "output": 0.16, "cache_read": 0.03 }
        }
      }
    }
  }
}
```

- The key under `models` must match the DeepInfra model name exactly; it is passed through as the model.
- `limit.context` is the model's context window and `limit.output` the per-request output cap you want.
- `cost` is in USD per million tokens and only drives opencode's cost display.
- Add `"tool_call": true` or `"reasoning": true` when the model supports tools or reasoning.

Fetch the current context window and prices for any model from the catalog:

```bash
curl -s "https://api.deepinfra.com/v1/openai/models?filter=with_meta" \
  | jq '.data[] | select(.id == "nvidia/NVIDIA-Nemotron-3.5-Lightning").metadata | {context_length, pricing}'
```

## Run opencode in a DeepInfra Sandbox

For unattended runs on code you don't want on your machine, run opencode inside a [Sandbox](/sandboxes/overview). The sandbox image has `curl`, `node` and `npm`, so the standard installer works, and `opencode run --auto` drives the agent without a terminal, approving tool calls as it goes:

```python
import os
from deepinfra import Sandbox

sb = Sandbox.create(timeout="30m")
sb.exec("bash", "-lc", "curl -fsSL https://opencode.ai/v2/install | bash")

sb.fs.write("/workspace/hello.py", b"def add(a, b):\n    return a - b\n")
r = sb.exec(
    "bash", "-lc",
    "export PATH=$HOME/.opencode/bin:$PATH DEEPINFRA_API_KEY=" + os.environ["DEEPINFRA_API_KEY"] +
    " && cd /workspace && opencode run --standalone --format json --auto"
    " -m deepinfra/deepseek-ai/DeepSeek-V4.1-Flash-1017"
    " 'Fix the bug in hello.py so add() returns the sum.' < /dev/null",
    timeout="10m",
)
print(r.stdout)
print(sb.fs.read("/workspace/hello.py"))
sb.terminate()
```

The `< /dev/null` matters: `opencode run` waits on stdin, and `exec` never closes it. Sandboxes accept no inbound connections, so `opencode run` is the way in; `opencode attach` to a server inside the sandbox is not possible from outside.
