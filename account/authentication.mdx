This page covers authenticating **API requests**. For signing in to the dashboard itself, see [Signing In](/account/signing-in).

DeepInfra supports two authentication methods:

1. **API keys** — long-lived tokens for your own use, limited to the scopes you give them
2. **Scoped JWTs** — short-lived, scope-limited tokens you can issue to third parties

## API keys

Get your API keys from the [Dashboard](https://deepinfra.com/dash/api_keys). Use them in the `Authorization` header:

```bash
Authorization: Bearer $DEEPINFRA_API_KEY
```

### Scopes

Each API key has scopes that say what it may do. You choose them when you create the key and can change them at any time on the key's page in the dashboard. A new key starts with `inference`, `models:read`, `account:read`, `lora:read` and `voice:read`: enough to run and look up models.

Where an area has two scopes, the `:read` one only reads and the full one also creates, changes and deletes. The full one includes its `:read` scope, so a key never needs both.

| Scope | What the key may do |
|---|---|
| `inference` | Run models: chat and text completions, responses, embeddings, images, speech, transcription, video and tokenization, including the OpenAI- and Anthropic-compatible endpoints and realtime voice |
| `models:read` | List and look up models, including your private ones, with their docs and input and output schemas, and read your custom deployments: their details, stats, logs and config history, and which GPU configurations are free to deploy on |
| `models` | Also manage your private models and custom deployments: change or delete models, and deploy, start, stop, update, rebalance and delete deployments |
| `account:read` | Read the account's profile, rate limits and GPU pool |
| `lora:read` | List and read your LoRA adapters and the ones available for a model |
| `lora` | Also create, update and delete LoRA adapters |
| `voice:read` | List and read your voices |
| `voice` | Also add, edit and delete custom voices |
| `account_scoped_jwt:read` | [Inspect scoped JWTs](#inspect-a-jwt) |
| `account_scoped_jwt` | Also [create scoped JWTs](#create-a-scoped-jwt) signed by this key |
| `batch` | Create, list and cancel [batch jobs](/batch/introduction), and manage their files |
| `compute:sandbox` | Create, run and manage [sandboxes](/sandboxes/overview) |
| `compute:agents` | Create, run and manage [agents](/agents/introduction) |
| `compute:containers` | Rent and manage [GPU containers](/gpu-instances/overview) |
| `billing:read` | Read usage, invoices, key spending limits and request costs |
| `metrics` | Query the account's usage metrics |

Speaking with a voice runs a model, so it needs `inference` as well as `voice:read`.

Each endpoint's page in the API Reference names the scope a key needs to call it. The [interactive API explorer](https://api.deepinfra.com/docs) can also filter endpoints by scope.

A request the key's scopes do not allow is refused with `403` and names the missing scope:

```json
{"detail": {"error": "this API key does not have the 'billing:read' scope"}}
```

Some actions are never open to an API key, whatever its scopes: managing API keys, changing payment details, setting spending limits and topping up all need a dashboard login.

<Note>
Keys created before scopes existed show **Unset** in the dashboard. They keep everything listed in the table above, but not scopes DeepInfra adds later. To limit such a key, or to give it a newer scope, choose its scopes on the key's page.
</Note>

## Scoped JWT

Scoped JWT tokens let you grant limited inference access to third parties without sharing your API key. You can restrict the token by:

- **Models allowed** — specific model(s) only
- **Expiration** — time-limited (up to 1 year)
- **Spending limit** — maximum USD spend

Usage is counted against the API key that was used to sign the JWT.

A scoped JWT can do no more than the key that signed it: it has that key's [scopes](#scopes), as they are at the time of each request. Creating a JWT needs the `account_scoped_jwt` scope and inspecting one needs `account_scoped_jwt:read`. A JWT signed by a key without `inference` cannot run models.

### Create a scoped JWT

```bash
curl -X POST "https://api.deepinfra.com/v1/scoped-jwt" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $DEEPINFRA_API_KEY" \
  -d '{
      "api_key_name": "auto",
      "models": ["deepseek-ai/DeepSeek-V4-Flash-0731"],
      "expires_delta": 3600,
      "spending_limit": 1.0
  }'
```

Response:

```json
{"token": "jwt:eyJhbGciOiJIUzI1NiIsImtpZCxxxxxxxxxxxxxxxxxx"}
```

This creates a token limited to `deepseek-ai/DeepSeek-V4-Flash-0731`, expiring in 1 hour, with a $1.00 spending limit.

**Optional fields** (omit to remove restriction):
- `models` — allow any model
- `expires_delta` — no expiration (defaults to 1 year)
- `spending_limit` — no spending limit
- Use `expires_at` (unix timestamp) instead of `expires_delta` if preferred

### Inspect a JWT

```bash
curl "https://api.deepinfra.com/v1/scoped-jwt?jwtoken=XXXX" \
    -H "Authorization: Bearer $DEEPINFRA_API_KEY"
```

```json
{
  "expires_at": 1738843515,
  "models": ["deepseek-ai/DeepSeek-V4-Flash-0731"],
  "spending_limit": 1
}
```

### Use a scoped JWT

Use it exactly like a regular API key in the `Authorization` header:

```bash
curl "https://api.deepinfra.com/v1/openai/chat/completions" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $SCOPED_JWT" \
  -d '{
      "model": "deepseek-ai/DeepSeek-V4-Flash-0731",
      "messages": [{"role": "user", "content": "Hello!"}]
    }'
```

Requests using disallowed models, expired tokens, or over-budget tokens will be rejected.
